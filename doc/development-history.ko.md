# 개발·검증 이력

SlideFill은 사용자의 프로젝트입니다. 사용자가 아이디어·요구사항·범위·검증 결정을 정하고, Claude와 Codex가 AI 개발 도구로 참여했습니다. 이 표기는 실제 작업 역할을 설명하며 독립적인 정확성 인증을 뜻하지 않습니다.

## 8차 측정 이전

Claude(Anthropic)는 사용자와 Claude Code에서 초기 설계·구현, 공개 파일 7차까지의 측정과 v0.1.0/v0.2.0 릴리즈에 참여했습니다. 기존 이력과 Claude의 기여 표기를 유지합니다. 당시 릴리즈의 근거는 기존 v0.2.0 노트에 남아 있습니다.

## Codex 참여: 8차 측정부터 v0.3.0까지

Codex(OpenAI)는 고정한 v0.2.0 코드의 8차 측정부터 이번 릴리즈까지 참여했습니다. 측정 자체와 이후 구현·검증·문서화·배포 준비를 포함합니다.

- **8차 측정:** 처음 보는 공개 통합 문서 8개 중 6개가 보고서를 생성하고 복합 양식 2개는 거절했습니다. 파일별 첫 검사 통과 문장 묶음 18/18개가 원본과 맞았지만 작은 표본의 한정된 관측입니다. 실제 PowerPoint로 보고서 6개·9슬라이드를 열었습니다. 빈 차트·연도/단위 누락·맞는 문장의 과잉 차단을 수정 전에 기록했습니다. v0.2.0 측정이며 v0.3.0의 새 정확도 점수가 아닙니다.
- **수정과 범위를 정한 표 지원:** 관측한 차트·연도·단위·문장 차단을 고치고 알 수 없는 회계연도 종료월을 추측하지 않게 했습니다. 문법을 명시한 다층 머리글·인원 구간 단가표·반복 조직/직종 블록·행 그룹을 지원했습니다. 모호한 업무 의미는 여전히 사용자가 판단합니다.
- **자동 CPU 검증:** 미리보기·저장에 독립 원본 재구성, 정확한 유리수 집계, 표시 값, 차트 캐시와 내장 엑셀 대조를 연결했습니다. 알려진 불일치는 저장을 차단하고 검산하지 못한 범위는 표시합니다. 새 로컬 모델이나 앱 의존성을 추가하지 않았습니다. 작은 정수·유리수·반올림 핵심을 Dafny로 증명해 앱에서 사용하지만 원본 변환·UI·일반 통계·모든 업무 의미의 증명은 아닙니다. [설계와 신뢰 경계](verification-design.ko.md), [바이너리·반올림 지원](binary-verification.ko.md)을 참고하세요.
- **빌드·배포 점검:** 실제 빌드에서 기존 테스트 675개와 검증 테스트 91개가 통과했고 배포 EXE 스모크, 소스/아카이브 개인정보 점검과 구성요소 고지를 확인했습니다. 개인 설정·공개 측정 원본·비공개 근거·VM 디스크·Windows 미디어는 배포에서 제외합니다.
- **환경·렌더링:** 배포할 동일 EXE가 Office·별도 Python이 없는 새 오프라인 Windows 10 Pro 19045.3803 VM에서 19개 사례를 통과해 보고서 18개를 만들었습니다. 호스트의 실제 PowerPoint 16.0.20326.20232가 게스트 보고서 18개와 호스트 보고서 18개, 총 44슬라이드를 렌더링했습니다. 게스트 슬라이드 이미지는 시각 검토한 호스트 이미지와 바이트 단위로 같았습니다. 설치한 VM은 재사용할 수 있게 보존했습니다. VM 촬영이 안정적으로 완료되지 않아 README 데모는 Windows 10 호스트에서 같은 UI 소스로 촬영합니다. [환경 시험의 정확한 범위](testing-alternatives.ko.md)를 참고하세요.

EXE는 18,655,237바이트, SHA256 `d19d0404311b22f42fa6dc36edc6c384e591030d59d6906179dae6efe373d64f`입니다. 문서·데모 변경은 이 검증된 런타임을 바꾸지 않습니다.

## 입증하지 않은 것

8차 입력은 수정 후 회귀 자료가 됐습니다. 이후 처음 보는 새 파일의 공정 정확도 측정은 없습니다. 비공개 회사 파일·Windows 11·두 번째 물리 PC·독립적인 사람의 직접 조작·모든 차트의 실제 데이터 편집 창은 미시험입니다. 자동 조작 데모를 사람의 사용성 시험으로 세지 않습니다. 원하지 않은 지표를 고를 수 있고 미지원 입력은 부분 검증으로 남을 수 있습니다. 검사 통과는 명시한 계약 범위이며 앱 전체의 증명이나 원본의 진실성 보장이 아닙니다.

원본 코드·문서는 [MIT](../LICENSE)를 유지하고 구성요소는 [각자의 조건](../THIRD-PARTY-NOTICES.md)을 따릅니다. 데모는 직접 만든 가상 자료를 씁니다. 비공개 Windows 미디어나 제3자의 원본 통합 문서·템플릿은 앱과 배포하지 않습니다.

## GitHub 커밋 기여 표기

README에는 프로젝트의 역할과 이력을 적습니다. GitHub는 커밋 메타데이터와 계정에 연결된 이메일로 작성자를 연결합니다. 이 프로젝트에서 Codex가 참여한 변경에는 본문 뒤 빈 줄 다음에 아래 줄을 한 번 넣습니다.

```text
Co-authored-by: Codex <noreply@openai.com>
```

이는 [공식 Codex 소스](https://github.com/openai/codex/blob/main/codex-rs/ext/git-attribution/src/world_state.rs)의 표기입니다. [GitHub 공동작성자 형식](https://docs.github.com/en/pull-requests/how-tos/commit-changes/creating-a-commit-with-multiple-authors)을 따르고 사람의 작성자와 실제 참여한 도구를 사실대로 유지합니다.

v0.3.0 커밋 `280af57`은 본문에 Codex 참여를 설명했지만 이 줄을 누락했습니다. 이번 후속 문서 커밋에는 정식 공동작성자 표기를 넣고 앞으로의 규칙을 기록합니다. 공개한 v0.3.0 태그와 검증한 EXE는 원래 스냅샷을 유지합니다.

## 릴리즈 상태 — 2026-11-09

기존 수용 검사가 완료된 v0.3.0을 사전 릴리즈에서 GitHub 정식 릴리즈로 전환했습니다. 버전·릴리즈 태그·EXE·배포 파일 8개는 검증한 동일 산출물입니다. 문서에 적은 입력·검증·환경의 지원 범위와 한계는 계속 적용됩니다.

## 미출시 수치 신뢰성 개선 — 2026-11-09

Codex가 사용자와 함께 `13dfc27` 기반의 격리된 개발 브랜치에서 작업을 이어갔습니다. 공개한 v0.3.0 EXE는 바꾸지 않았습니다. 제한된 수식 캐시·의존 관계의 독립 검사, 계산 중간값의 정확한 유리수 유지, 수치 문구·Word 평균의 독립 재구성, 차트 정밀도·서식 검사, 독립 검증이 불완전하면 저장을 거부하는 동작을 추가했습니다. [실제 검사 계약과 남은 한계](reliability-hardening.ko.md)를 참고하세요.

최종 소스는 `build.bat`에서 **코어 테스트 675개와 검증 테스트 137개**를 통과했습니다. Dafny 4.11.0을 새로 실행해 핵심의 실행 계약 6개와 보조 정의에 대해 검증 단위 9개·오류 0개를 확인했고 생성된 클래스가 앱에 포함한 코드와 일치했습니다. 이는 제한된 핵심의 증명이며 앱 전체의 증명은 아닙니다.

실제 Excel 16.0.20326.20232로 저장한 합성 자료의 지원 수식 26개를 검사했고 미지원 비교 사례 2개를 명시적으로 거부했습니다. 정확한 산술과 다른 상쇄 계산 캐시와 의도적으로 오래되게 만든 캐시도 거부했습니다. 실제 PowerPoint 16.0.20326.20232가 보고서 4개·슬라이드 4개를 열고 렌더링했으며 차트 통합 문서 2개도 열었습니다. 영문·국문 보고서, 전체 수식 표, 큰 소수 금액 표를 시각 검토했습니다. 첫 과밀 시험 표는 넘침 경고가 있었고 실제로 잘렸습니다. 근거를 보존하고 합성 템플릿의 여백을 고친 뒤 렌더링을 반복했습니다. 임의 레이아웃의 정확성을 보장하는 결과는 아닙니다.

UI는 영어·한국어, 900×600·1200×800에서 저장 차단과 창 종료 콜백 정리를 포함한 스크립트 검사를 통과했습니다. 이 회귀·변조·실제 Office 사례는 새로운 미관측 회사 파일의 정확도 측정이 아닙니다. 이번 개발 빌드로 새 VM·Windows 11 검사는 하지 않았습니다. 원본 진실성, 업무 범위·가중치·최신성, 모든 문장과 임의 템플릿 레이아웃은 고지한 사람의 검토가 필요합니다. 새 의존성이나 라이선스 체계는 추가하지 않았습니다.

로컬 검증 EXE는 18,694,459바이트, SHA256 `3d11c97604efaa8f5c41751e8ed773e254f7fedb84a02bc8b0bc74ff1d342ff8`입니다. 빌드 스모크와 동일 EXE의 다섯 사례를 통과했습니다. 정상 생성, 오래된 수식 캐시 거부, 미지원 수식 거부, 차트 정밀도 손실 거부, 기존 출력 파일 보존입니다. 새로 공개한 릴리즈는 아닙니다.
