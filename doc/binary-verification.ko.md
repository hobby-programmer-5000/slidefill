# 바이너리 원본·그룹·반올림 검증

확장 기능은 기존 [앱 자동 검증](verification.ko.md) 안에서 동작합니다. 실행에 Office나 사용자용 검증 명령이 필요하지 않습니다. 개발 중 독립 시험 자료를 만들고 표시 결과를 비교할 때만 실제 Excel을 사용합니다.

엄격한 수식·정밀도 변경은 **아직 릴리스하지 않은 개발 소스**를 설명합니다. 아래의 이전 실물 검사는 기록된 당시 산출물의 근거이며 새 EXE의 근거가 아닙니다. [현재 신뢰성 계약](reliability-hardening.ko.md)을 참고하세요.

## 원본 형식

- `verification/compound.py`는 CFB FAT/DIFAT·MiniFAT 체인에서 루트 Workbook/Book 스트림을 찾고 범위·순환을 검사합니다. `binary.py`는 지원하는 BIFF2–5/8 XLS 셀·유니코드 공유 문자열과 이어지는 기록·압축 숫자·참/거짓·오류·수식 저장 결과·병합·날짜 기준을 읽습니다.
- 독립 XLSB 리더는 ZIP 관계와 바이너리 기록에서 지원 숫자·문자·참/거짓·오류 셀, 수식 캐시·공유 문자열·서식·병합·1900/1904 날짜 기준을 읽습니다. 빈 문자열 캐시는 기존 calamine 생산 어댑터에 맞춰 빈 셀로 정규화합니다.
- 이름이 `.xls`인 HTML·구분 텍스트 내보내기도 별도로 검사합니다. 평면 HTML 표의 셀 위치·병합·행/머리글 그룹과 생략 가능한 셀/행 닫기 태그를 처리하며 셀 안의 중첩 표는 별도 시트로 보존하고 바깥 셀에는 대괄호 시트 참조를 남깁니다. 지나치거나 모호한 병합·잘못된 중첩은 미지원입니다.
- 0초를 포함한 정확한 마이크로초 정밀도의 ODS 하루 미만 시간은 ISO 시간 글자로 바꿉니다. 음수·하루 이상·더 세밀한 정밀도는 `-PT25H`·`PT0.0000001S`처럼 원본 표현 전체를 보존합니다. 표기와 셀 위치를 검산하며 숫자형 경과 시간으로 바꾸지는 않습니다. 년/월 기간 문법 등 미지원 표현은 부분 검증입니다. 저장 수식은 제한된 독립 문법으로 정규화할 수 있을 때만 검사하고 반복 수식은 미지원입니다. 통합 문서를 재계산하거나 수정하지 않습니다.
- 날짜 독립 재구성에는 지원하는 월·연도, 분기·연도, 숫자로 된 연도와 여덟 자리 날짜를 추가했습니다. `39 925` 같은 천 단위 공백 숫자도 검산합니다.

전체 파일 형식을 구현한 것은 아닙니다. CFB 입력과 바이너리 ZIP 부분별 예산은 128 MiB, 값 셀 예산은 200만 개입니다. 미지원 BIFF 통합 문서/작업공간 변형과 문자열/셀 문법은 부분 검증으로 남습니다. 범위를 정한 BIFF2/3/4 단일 시트·BIFF5/95 통합 문서·BIFF5/8 RSTRING 값은 아래 범위에서 검사합니다. 지원하는 XLSB 축약 기록은 아래에 설명합니다. 기존 원본 형식·표시 제한도 적용되며, 미지원 근거가 다른 곳의 확정된 불일치를 지우지는 않습니다.

수식 캐시를 읽는 것과 계산을 검사하는 것은 다릅니다. 바이너리 수식 표현을 독립 계산하지 않으므로 **사용한 XLS·XLSB 수식 셀은 부분 검증**으로 남습니다. 개발 앱은 확정된 불일치와 부분 검증 모두 저장을 거절하며 일반 값 셀의 기존 지원 범위는 유지합니다. 지원하는 XLSX·ODS 수식 문법·제한은 [별도 안내](reliability-hardening.ko.md#수식-문법과-제한)에 있습니다.

형식 근거는 Microsoft의 [CFB 머리글 명세](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/05060311-bfce-4b12-874d-71fd4ce63aea), [XLS 문자열 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/173d9f51-e5d3-43da-8de2-be7f22e119b9), [수식 캐시 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/39a0757a-c7bb-4e85-b144-3e7837b059d7), [XLSB 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xlsb/)입니다. ODS 값 유형은 [OASIS 스키마](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part3-schema/OpenDocument-v1.3-os-part3-schema.html)를 따릅니다. 제3자 파서 소스·런타임을 복사하지 않았으며 새 원본 코드는 기존 프로젝트 MIT를 유지합니다.

## 합계를 추정하지 않는 명시적 그룹

XLSX 계열 시트에 항목·값 머리글이 명시적으로 인접하고 실제 Excel 행 그룹 수준이 있으면 설명 표를 만듭니다. 상위 값이 하위 합과 다르더라도 원본 행·수준·값을 유지합니다. ‘Parent’라는 글자만으로 계층을 만들지 않습니다. 빈 행에서 구역이 끝나며 임의 피벗 구조나 업무상 소속 관계는 추정하지 않습니다.

`layouts._outlines`가 뷰를 만들고 `rawxlsx`·`oracle`이 수준과 행 범위를 독립적으로 읽어 확인합니다. 그룹 메타데이터가 업무상 소속을 인증하지 않는다는 설명을 보고서에 남겨야 합니다. 앱 자동 검사와 개발용 인증 검사 모두 그 설명을 삭제하면 거절합니다. 생성 전 범위 확인도 유지합니다.

## 실제 숫자 표시 경로의 반올림 증명

`numfmt._digits`는 유한 Decimal에 `kernel.round_decimal`, 정확한 Fraction에 `round_rational`을 호출합니다. 두 경로 모두 정확한 분수 `n/d`와 양의 배율 `s=10^places`를 씁니다. Python에서 `abs(n)*s/d`의 음이 아닌 정수 몫을 구한 뒤 연결 코드가 그 몫의 정의에 해당하는 정수 부등식을 확인하고 생성된 `RoundScaled`를 호출합니다.

계약은 반환 정수 `r`가 다음 반올림 구간에 있음을 증명합니다.

```text
n >= 0: (2*r-1)*d <= 2*n*s <  (2*r+1)*d
n <  0: (2*r-1)*d <  2*n*s <= (2*r+1)*d
```

따라서 정확히 절반이면 0에서 멀어지는 방향으로 반올림합니다. 정수 계수와 십진 지수로 Decimal 결과를 복원합니다. 아래 집계 오차 합을 포함한 현재 핵심은 소스 정의 7개·실행 메서드 6개에 대해 검증 단위 9개·오류 0개이며, 경계·부호·나머지 판단이 잘못된 구현은 거절됐습니다. [증명 재현](../verification/proofs/README.ko.md)을 참고하세요.

검사한 몫의 범위와 양의 배율·분모를 전제로 주어진 정확한 십진수·유리수의 반올림 판단을 증명합니다. Decimal/Fraction 추출·Python 정수 연산·앞선 배율/표기 선택·글자 배치·변환 정책은 테스트·신뢰 경계입니다. IEEE-754 하드웨어나 모든 표시 서식의 증명은 아닙니다. 독립 원본 근거·텍스트 검사도 `numfmt`를 공유하므로 별도의 독립 서식기는 아닙니다.

## 앞선 셀에 연결되는 XLSB 축약 기록

12–18번 기록은 열 필드를 생략하고 같은 행의 직전 셀 다음 열을 뜻합니다. 빈칸·RK 숫자·오류·참/거짓·실수·인라인 글자·공유 글자 유형입니다. 각 행은 표준 셀 기록으로 시작해야 합니다. 빈 축약 셀도 한 열을 차지하며 표준 기록으로 열을 건너뛸 수 있습니다. 잘린 값·중복/역순 열·시트 범위 초과는 거절합니다. `readers._expanded_xlsb`가 메모리 ZIP 안에서 축약 셀을 표준 기록으로 바꿔 기존 calamine에 전달하고, `verification.binary.xlsb`는 원본 바이트를 별도로 해독합니다. 원본 파일은 다시 쓰지 않습니다. calamine이 빈칸으로 내놓던 오류 셀·오류 캐시도 생산 경로에서 보존합니다.

형식의 근거는 작성자의 [SheetJS 관찰 기록](https://github.com/SheetJS/notes/blob/main/xlsb_short_records/README.md)이며 Microsoft가 공표한 축약 기록 명세라는 뜻은 아닙니다. 파서 코드나 제공자 시험 파일은 복사하지 않았습니다. 실제 Excel 시험 자료에서 만든 합성 변형 두 개를 Excel 16.0에서 읽기 전용으로 열어 값을 대조했습니다. 이 실물 확인은 빈칸·RK·공유 글자와 두 날짜 기준을 포함합니다. 축약 값 유형 일곱 가지는 직접 작성한 합성 파일·생산 리더·독립 리더 테스트로 확인합니다. 행의 첫 셀까지 축약한 실험은 실물 열기에 실패해 거절 회귀 검사로 남겼습니다. 모든 리더가 그 배치를 같은 방식으로 처리한다는 주장은 아닙니다.

## 정확한 집계와 원본 디코딩 오차

명시한 그룹의 합계·곱·평균·건수·비율은 읽어낸 유한 숫자의 십진 표기를 정확한 Fraction으로 유지합니다. 행별 곱·행 합·그룹 합·평균 나눗셈 중간에 이진 반올림을 하지 않습니다. `kernel.sum_rationals`가 공통 분모로 바꿔 실제 생성된 `Sum`을 호출합니다. 표시하거나 필요한 숫자 컨테이너로 변환할 때까지 정확한 중간값을 유지하므로 `10^16 + 1 - 10^16`은 1, `0.1 + 0.2`는 `3/10`입니다. 앱 평균·차이·비율도 유리수 중간값을 유지합니다. 사용자가 요청한 행이나 그룹 소속을 바꾸는 것은 아니며 디코딩 전에 잃은 자릿수를 복원하지는 못합니다.

독립 계산 근거 리더가 원본 파일에서 피연산자를 다시 읽습니다. 지원하는 십진수→이진수→짧은 십진 표기 변환도 별도로 확인합니다. 정수 손실은 거절하며 달라진 소수는 유효 십진 숫자가 17자리 이하여야 하고 차이는 입력 1ULP 이하여야 합니다. 더 높은 정밀도는 부분 검증입니다. 이 기준은 지원 범위 정책이며 모든 디코더에 대한 정리가 아닙니다.

정확한 원본의 행 합/곱을 `r_i`, 독립 재구성한 디코딩 뒤의 행 결과를 `d_i`라고 두면 `delta_i = d_i-r_i`, `e_i = abs(delta_i)`입니다. 생성된 `SumBound`는 임의의 유한 정수 배율 목록에 대해 다음을 증명합니다.

```text
S = sum(delta_i), E = sum(e_i), E >= 0, -E <= S <= E
```

연결 코드가 같은 길이·음이 아닌 오차 한계·각 항의 `-e_i <= delta_i <= e_i`를 확인하고 생성 코드를 부릅니다. 유리수 차이를 양의 공통 분모로 정수화한 뒤 복원합니다. 앱 검사는 `S`가 독립 재구성한 디코딩 뒤 합계와 원본 합계의 차이인지 대조합니다. 유지한 행이 `N`개인 평균/비율에서는 합계의 상한이 `E/N`이 됩니다. 행 수에 따른 추가 ULP 허용량은 없습니다. 집계 Fraction은 디코딩 뒤 정확한 유리수와 같아야 하며 기존 float 표현에 대한 호환 비교는 독립적으로 한 번 변환한 float를 요구합니다. 별도 차트 직렬화에는 2ULP 정책과 함께 정확한 정수 왕복·명시한 서식의 표시 정밀도 검사도 적용합니다.

현재 증명은 검증 단위 9개·오류 0개입니다. 차이를 두 배로 더하거나 오차 한계를 빼거나 마지막 항을 생략한 구현 세 가지는 동일한 계약에서 거절됐습니다. 주어진 오차들의 합에 대한 증명이며 원본 파서·Fraction/공통 분모 변환·십진/이진 변환 의미·모든 곱 구현·하드웨어·앱 전체의 증명은 아닙니다. 다른 통계/선택·서식 경로는 테스트·신뢰 경계입니다. 차트 캐시와 내장 엑셀 검사도 유지하며 정수나 명시한 표시 정밀도를 직렬화에서 잃으면 집계 허용 오차를 늘리지 않고 저장을 막습니다. General 차트에 원본 소수의 모든 자릿수를 약속하지는 않습니다.

원본 코드와 생성 계약은 기존 [MIT 라이선스](../LICENSE)(SPDX MIT, 별도 버전 번호 없음)를 유지합니다. 재사용 가능한 소스라는 프로젝트 방향에는 기존 MIT 유지가 적합하며 배포 시 고지를 보존해야 합니다. 새 의존성·모델·외부 런타임·라이선스 체계는 추가하지 않았습니다. 제3자 고지는 별도로 계속 적용됩니다. 실제 Office 시험 파일은 무시되는 로컬 근거로만 남기며 배포하지 않습니다.

## 구형 BIFF와 중첩 HTML 검증

독립 디코더는 범위를 정한 BIFF2/3/4의 단일 시트 바이너리 스트림, 바이트 인코딩을 명시한 BIFF5/95 통합 문서, BIFF5/8 RSTRING 값을 처리합니다. 생산 경로는 기존 xlrd를 쓰며 독립 경로는 이를 import하지 않습니다. 구형 원시 파일을 구분 텍스트 대신 바이너리로 인식합니다. BIFF2 정수/실수 셀, 지원하는 문자열·참/거짓·오류·수식 캐시와 구형 숫자 서식 인덱스를 읽습니다. BIFF2 특수 수식 캐시·BIFF4W/작업공간 변형·미지원 이어쓰기/문자열 문법·알 수 없는 코드페이지는 부분 검증입니다. 코드페이지가 없으면 ASCII 근거만 허용하며 로컬 인코딩을 추정하지 않습니다. 서식 있는 문자열의 글자는 보존하고 글자별 글꼴 구간의 순서/범위를 확인하지만 그 구간을 보고서 스타일로 재현하지는 않습니다. 사용한 수식 셀은 저장 값 해독이 수식 자체의 검산은 아니므로 부분 검증입니다.

Excel16.0에서 날짜 기준별 BIFF5 샘플 두 개를 만들었습니다. 구형 내장 날짜 서식14를 로캘 날짜의 표준 표현으로 정규화한 뒤32개 원시/형식 값과 열을 충분히 넓힌 뒤의 명시적 서식·글자 표시30개가 일치했습니다. 나머지 General 숫자 표시2개는 Excel의 열 너비에 영향을 받으므로 별도로 관측했습니다. 표시 비교에서 열을 넓히는 작업은 읽기 전용 문서의 메모리 안에서만 하며 저장하지 않습니다. BIFF2/3/4와 BIFF8 RSTRING은 직접 작성한 합성 파일로 확인했으며 과거 Excel 버전을 실행했다는 뜻은 아닙니다. 형식 근거는 작성자의 [OpenOffice 파일 형식 문서](https://www.openoffice.org/sc/excelfileformat.pdf)와 Microsoft의 [파일 형식 식별자](https://learn.microsoft.com/en-us/dotnet/api/microsoft.office.interop.excel.xlfileformat)를 대조했습니다. 제3자 파서 코드나 시험 자료를 복사하지 않았습니다. 원본 코드는 기존 MIT를 유지하고 의존성을 추가하지 않습니다.

HTML의 각 표는 문서 순서에 따라 별도 격자로 유지합니다. 안쪽 표는 바깥 셀 안에 있어야 합니다. 별도 시트로 옮기고 바깥 셀에는 자기 글자와 `Before [Nested 2] After` 같은 참조만 남겨 안쪽 숫자를 바깥 수치 셀에 중복 넣지 않습니다. 뒤쪽 행·같은 수준의 여러 표·다단계 중첩·병합·생략 가능한 셀/행 닫기 태그를 검사합니다. 생산 리더는 열린 표의 스택, 독립 리더는 별도로 해석하는 표 참조를 사용합니다. 중첩32단계·표256개·전체 병합 영역 셀200만 개로 제한합니다. 잘못된 중첩·닫지 않은 표·모호하거나 겹치는 병합을 지원한다고 주장하지 않으며 브라우저 DOM/CSS 배치 엔진은 아닙니다.

샘플의 바깥 값46·안쪽 값12/34·바깥 마지막 값10을 모두 보존하고 원본과 독립 연결합니다. 값 변경·중첩 참조 삭제·저장 결과 손상은 자동 검사를 계속 거칩니다. 아주 작은 표에는 자동 보고서 제안이 없을 수 있어 이번12개 보고서 샘플 검사는 명시한 참조 템플릿으로 수행했습니다. 자동 선택 규칙을 이번 작업에서 늘리지는 않았습니다.
