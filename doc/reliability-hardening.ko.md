# 수치 신뢰성: 개발 소스

이 변경은 **아직 릴리스하지 않았습니다.** 현재 개발 소스의 동작이며 배포된 v0.3.0 EXE의 기능을 뜻하지 않습니다. [개발 이력](development-history.ko.md)의 이전 Windows·Office 검증은 각 기록에 명시한 산출물에만 적용됩니다.

원본·계산·저장한 PowerPoint를 각각 검사해 사람의 숫자 대조 부담을 줄이는 것이 목표입니다. 원본이 사실인지, 선택한 지표가 올바른 업무 질문에 답하는지는 확정할 수 없습니다.

## 검사하는 것

| 단계 | 강제하는 검사 | 남는 경계 |
|---|---|---|
| 원본 | 독립 리더로 명시한 셀·조건·날짜·이름을 재구성하고, 지문으로 통합 문서·Word 문서 변경을 감지합니다. | 어떤 셀이 필요한지는 명시한 계산 근거가 정합니다. 검증기가 업무 범위를 별도로 선택하지는 않습니다. |
| 저장된 수식 | 별도의 제한된 계산기로 사용한 수식 캐시와 의존 셀을 정확한 산술과 대조합니다. 최신·순위 선택 범위의 수식은 최종 선택하지 않은 행도 포함합니다. | 전체 Excel 엔진이 아니며 원본을 재계산하거나 다시 저장하지 않습니다. 미지원 표현은 부분 검증입니다. |
| 산술 | 합·곱·평균·증감·비율의 중간값을 읽어낸 피연산자의 정확한 유리수로 유지하며, 지원하는 표시 반올림에는 증명한 정수 판단을 씁니다. | 파일 디코딩·알고리즘 선택·표시 서식은 테스트 코드입니다. 정확한 산술이 가중치·단위·업무 의미를 정하지는 않습니다. |
| 텍스트 | 바꾼 문단을 직렬화한 뒤 검사합니다. 직접·최신·순위 값은 원본 근거와 대조합니다. 수치 자리표시자 `전일대비`·`전주대비`·`평균대비`·`최고일`·`최저일`의 비교 산술·동률 시 최신 날짜 선택을 독립 재구성합니다. 계산·모델 해설 문장에는 입력 근거를 연결합니다. | 저장한 문장과 그 입력의 검사가 모든 문장 주장·해석·모델 문장의 증명은 아닙니다. |
| 표·차트 | 값·행/점 범위·순서·차트 캐시·참조한 내장 엑셀 셀을 원본과 연결한 기준과 대조합니다. | 표시 없는 기존 템플릿 내용과 임의 Office 배치는 수치 검사의 범위 밖입니다. |
| 저장 확정 | 임시 결과를 재검증하고 바이트·원본 지문을 다시 확인한 뒤 새 파일명으로만 확정합니다. | 파일시스템·실행 환경은 신뢰 경계입니다. 해시는 서명이나 원본의 진실성 인증이 아닙니다. |

**확정된 불일치와 독립 검산 범위의 공백 모두 저장을 막습니다.** 부분 검증 미리보기는 원인 확인에 쓸 수 있지만 일반적인 ‘그래도 만들기’로 우회할 수 없습니다. 원본을 바로잡거나 지원하는 참조를 고르거나 미지원 수식을 독립 검산 가능한 입력으로 단순화하세요. 별도 값 전용 파일을 만들 때 원본도 보관하세요. 값 전용 파일에는 SlideFill이 검사할 수식 이력이 없습니다.

## 수식 문법과 제한

`verification/formulas.py`는 앱의 계산 함수를 호출하지 않습니다. 유한한 숫자, 셀·범위 참조, 따옴표 시트명, 절대·공유 상대 참조, 괄호, `+ - * / %`, 정수 지수, 숫자 비교와 `SUM`, `AVERAGE`, `COUNT`, `MIN`, `MAX`, `ABS`, `INT`, `ROUND`, `ROUNDUP`, `ROUNDDOWN`, `IF`, `TRUE`, `FALSE`를 지원합니다. Excel의 음수·퍼센트·거듭제곱 우선순위를 명시합니다. 지원하는 숫자·참/거짓·형 변환 사례에 한정됩니다.

배열·데이터 표 수식, 외부 연결, 알 수 없는 함수·이름, 순환, 숫자가 아닌 비교와 미지원 형 변환은 부분 검증입니다. XLS·XLSB 수식 셀은 캐시를 읽을 수 있어도 바이너리 수식 자체를 독립 계산하지 않으므로 부분 검증입니다. ODS는 같은 제한 문법으로 정규화할 수 있는 수식만 검사하고 반복 ODS 수식 셀은 미지원입니다. 이 형식의 일반 값·빈칸은 기존 값 검증 범위를 유지합니다.

예산은 수식 8,192자·토큰 2,048개·문법/의존 깊이 64·의존 셀 100,000개·정확한 결과 65,536비트·절댓값 1,000 이하 정수 지수입니다. 넘으면 검증 완료가 아닌 미완료로 남습니다. 명시한 사용·선택 범위와 그 수식 의존 셀을 검사하며 통합 문서 전체 감사는 아닙니다.

정수는 정확히 일치해야 합니다. 정수가 아닌 수식 캐시는 2ULP 비교 정책을 사용합니다. Excel의 부동소수점 결과가 정확한 산술 계약과 다를 수 있습니다. 예를 들어 상쇄로 정수 한 단위를 잃으면 이를 정답으로 재현하지 않고 거절합니다. Excel에서 재계산해 저장하는 것은 여전히 좋은 입력 준비이지만, 이 검사 우회 조건은 아닙니다.

## 정밀도와 수학적 정의

앱의 입력 디코더는 이미 정수·float를 제공합니다. `Fraction` 계산은 읽어낸 유한 피연산자의 십진 표기를 정확하게 유지하며 그 전에 잃은 자릿수를 복구하지는 못합니다. 독립 원본 재구성은 정수 손실을 거절합니다. 십진수→이진수→짧은 십진 표기로 값이 달라지는 경계는 원본 유효 십진 숫자 17자리 이하·차이 입력 1ULP 이하일 때만 지원합니다. 더 높거나 알 수 없는 정밀도는 부분 검증입니다. 변하지 않은 정확한 피연산자는 그 정규화가 필요하지 않습니다. 모든 스프레드시트 디코더에 대한 정리가 아닌 지원 범위 규칙입니다.

예를 들어 `10^16 + 1 - 10^16`은 `1`이며 `0.1 + 0.2`는 표시하거나 숫자 컨테이너로 바꿔야 할 때까지 정확한 유리수 `3/10`입니다. 상대 증감률은 `(현재 - 기준) / abs(기준)`이고 기준이 0이면 유보합니다. 퍼센트포인트 변화는 명시한 배율의 차이입니다. 지원하는 십진 표시에서 정확히 절반은 0에서 멀어지는 방향으로 반올림합니다.

차트는 이진 숫자 컨테이너가 필요합니다. 그 변환을 정확히 통과하지 못하는 정수는 거절하며, 명시한 지원 숫자 서식에서는 캐시와 내장 데이터가 요구한 정밀도로 표시되는지도 검사합니다. 따라서 정확한 표 소수는 허용해도 같은 값의 차트를 거절할 수 있습니다. General 표시와 2ULP 직렬화 검사가 차트에 원본 소수의 모든 자릿수를 보존한다는 약속은 아닙니다. 공유 `numfmt` 서식기는 테스트·신뢰 경계이며 독립적으로 증명한 Office 렌더러가 아닙니다.

행마다 같은 가중치를 주는 비율 평균과 분자 합계/분모 합계는 다릅니다. `100/100`과 `0/900`의 두 방식은 각각 `50%`와 `10%`입니다. 비율 평균의 자동 의심 신호로 이 선택을 알리며 없는 분모·가중치를 만들어 내지 않습니다. **내용 바꾸기(Ctrl+R)**에서 필요한 지표를 확인하세요.

Word 연결 비교는 원본 기간·전후 기간 수·산술평균·변화 문구를 독립 재구성하고 사건이 있는 기간은 제외합니다. 기간 수가 다른 행은 하나의 공통 머리글로 잘못 적지 않고 행마다 표시합니다. 인용이 원본 DOCX에 있는지 대조하고 DOCX가 바뀌면 저장을 막습니다. 지원하는 계산·인용의 일관성을 확인하는 것이며 사건이 숫자 변화를 일으켰다는 증명은 아닙니다.

## 계산에서 문장까지 정보 보존

선택적 통찰의 숫자 대응은 반올림한 실수 문자열 대신 제한된 정확한 십진 동일성을 사용합니다. 올바른 동등 십진·묶음·과학 표기는 같을 수 있고 인접한 큰 정수와 다른 긴 소수는 구분합니다. 잘못되거나 과도한 토큰은 거부합니다. 날짜·분기 제외는 별도이며 숫자의 크기를 대조할 뿐 부호·단위·대상·의미의 인증은 아닙니다. 일부 근거 생성기가 과학 표기 전체를 유지하지 못하면 검사기의 표기 지원과 별개로 보수적으로 거부할 수 있습니다.

통찰 편집기는 선택을 저장하기 전에 이 좁은 검사를 합니다. 거부하면 기존 선택을 유지하고 편집기를 열어 둡니다. 표시한 근거의 숫자를 사용하거나 칸을 비워 계산 문장으로 돌아가세요. core도 저장 선택을 재사용할 때 검사하므로 외부에서 바꾼 잘못된 문장은 수치 경고와 함께 계산 문장으로 대체됩니다. 임의 사용자 문장에 모델 후보의 모든 의미 규칙을 적용하는 경로는 아닙니다.

계산한 `year`·`prev` 근거가 정확한 상대 변화 비율을 전달하고 파일 간 방향은 반올림한 문장을 읽지 않고 이 타입 정보를 사용합니다. 포인트 차이나 문장만 있는 근거를 상대 백분율로 바꾸지 않습니다. `0.0%`로 표시될 비영 변화는 `0.05%` 미만 증가·감소로 설명하고 경계에서는 명시한 절반 올림 규칙을 씁니다. 선택 지문에도 정확한 변화가 포함됩니다. 기간·기준 이름이 같아도 업무상 비교 가능성을 확정하지 않으며 상관·인과 추론은 없습니다.

**내용 바꾸기(Ctrl+R)** 약도는 유한 정수·실수·Fraction 자료를 받고 Boolean·유한하지 않은 값을 제외하며 누락 구간과 양·음 막대의 영 기준선을 유지합니다. 정확한 정규화 뒤 화면 좌표를 실수로 바꿉니다. 약도가 저장 차트 검사나 실제 Office 확인을 대신하지는 않습니다.

합성 회귀 검사는 잘못 허용했던 낮은 자릿수, 동등 표기, 잘못된 저장·편집 선택, 아주 작은 반대 방향과 배율, 누락 구간·영 기준선, 큰 유리수 차트 도형을 다룹니다. [연구 방법](research-methods.ko.md)은 방법의 논문 근거와 앱 적용 추론을 구분합니다. 이 경계 검사들이 앱 전체의 새 증명은 아닙니다. 수동 내용 선택에는 아직 완전한 스키마 변경 계약이 없습니다.

## 검증 완료로 말할 수 있는 것

검증 완료는 **이번 보고서에서 명시한 지원 입력 값·계산·저장 표현이 구현된 검사를 통과했다**는 근거입니다. 원본 정확성·의도한 범위·최신성·단위·모든 문장·모든 시각 배치의 인증은 아닙니다. 그 결정들을 확인하고 고객에게 공유하기 전에 완성 보고서를 살펴보세요. 수치 계산에 모델은 쓰지 않으며 선택형 AI 문장은 별도로 검토합니다.

생성된 Dafny 핵심은 명시한 정수 계약을 증명하며 파서·원본 계산 근거·알고리즘·앱 전체를 증명하지는 않습니다. 유한 전수·변이 검사와 선정한 실제 Excel·PowerPoint 사례는 서로 보완하는 근거이며 미지 회사 파일 정확도 점수가 아닙니다. [검증 설계](verification-design.ko.md), [숫자 디코딩·증명 경계](binary-verification.ko.md), [증명 재현](../verification/proofs/README.ko.md)을 참고하세요.

새 원본 코드는 기존 MIT를 유지합니다. 의존성·모델·가중치·제3자 파서 소스를 추가하지 않았으며 기존 구성요소 고지는 계속 적용됩니다.
