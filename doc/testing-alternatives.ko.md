# 환경·사용 시험의 대체 방법

[현재 한계](limits.ko.md)를 보완하는 검사입니다. 자동 모방은 모방으로 기록하며 공개 표본을 비공개 회사 파일로 부르지 않습니다. 후속 빌드·실제 Office 렌더링·깨끗한 Windows 검증 결과는 아래에 구분해 기록합니다.

| 부족한 근거 | 가능한 대체 | 확인하는 범위 |

|---|---|---|

| 사용이 허용된 비공개 업무 파일 | 출처·해시·시험 허용 근거를 로컬에 기록한 공식 공개 업무 표본 | 해당 표본·스키마의 호환성. 특정 회사 파일의 호환성을 대신하지 않습니다. |

| 사람이 직접 사용하는 과정(현재 필수 아님) | 합성 입력·격리 설정·이벤트·기록한 대화상자 응답으로 실제 Tk UI를 실행하고 화면 확인 | 지정한 경로와 보이는 상태. 사람의 이해나 예상 밖 조작까지 확인하지 않습니다. |

| Office 없는 Windows | 시험할 앱만 넣고 Office를 설치하지 않은 새 Windows Sandbox 또는 VM | 실제로 검사한 산출물이 해당 환경에서 실행됨. 호스트의 Office 렌더링이나 일반 파일시스템 샌드박스로 대신할 수 없습니다. |

## 공개 표본과 이용 범위

Microsoft는 [데이터 시험용 Financial Sample 통합 문서](https://learn.microsoft.com/en-us/power-bi/create-reports/sample-financial-download)를 명시적으로 제공합니다. 표본 매출·이익 자료이며 비공개 고객 파일은 아닙니다. 해당 페이지를 통해 내려받아 지문을 기록하고 로컬 미리보기·자동 검증·저장에 사용했습니다. 소스·배포 트리 밖에 보관합니다. 이 로컬 시험의 근거는 표본을 시험해 보라는 공식 안내이며, 일반적인 재배포나 상업용 템플릿 권한을 주장하지 않습니다. 다른 저장소의 MIT 표시를 이 통합 문서에 적용하지 않습니다.

이전 공개 입력 여덟 개는 계속 회귀 사례입니다. 새 표본은 호환 관측 하나를 추가할 뿐 통계적으로 의미 있는 미지 회사 파일 성공률이 아닙니다. 원본 프로젝트 코드·문서는 기존 MIT를 유지하고 제3자 자료 권리는 별도로 다룹니다.

## 이전 시험 결정

2026-11-08 앞선 사용자 결정에서는 해당 범위에 기존 샘플 사용과 자동 샘플 검사로 충분하다고 정했습니다. 별도 실제 사용자 시험과 Office 없는 Windows 시험은 그 앞선 검사에서 **사용자 결정에 따라 SKIPPED**였습니다. 아래의 후속 요청으로 Windows 시험을 다시 수행했고, 별도 실제 사용자 시험은 계속 제외합니다. 실제 사용 중 문제가 보고되면 그때 해결합니다. 그 앞선 검사에서는 Windows 기능·가상 머신·다른 오피스 제품을 설치하지 않았습니다.

Office 없는 Windows 시험의 대상은 오픈소스 오피스가 아니라 Office를 설치하지 않은 상태에서 SlideFill 자체가 실행·저장되는지였습니다. 파일 형식 관례와 실행 의존성은 별개입니다. 그 앞선 검사에서는 선택적 환경 시험을 제외했으므로 깨끗한 Windows 호환성 결과를 주장하지 않았습니다.

## 이전 소스·구형 EXE 자체 실행 시험(2026-11-08)

후속 요청으로 현재 Windows 호스트에서 앱 자체를 시험했습니다. 현재 소스와 변경하지 않은 기존 EXE를 합성 설정·샘플 입력만 있는 별도 폴더에 복사했고 개인 설정은 복사하지 않았습니다. 실제 창에서 키보드 저장 명령으로 소스 보고서3개와 EXE 보고서1개를 만들었습니다. 각 버전의 자체 시험 모드에서도 정상 입력→잘못된 템플릿→정상 입력을 실행해 예상 종료 코드0/1/0을 확인했습니다. 오류 뒤 정상 실행은 별도 프로세스로 재시작한 경우의 확인입니다.

소스의 자체 시험 프로세스에는 socket 연결·subprocess/startfile 실행·win32com/comtypes import를 막는 Python audit hook을 해당 프로세스 안에서만 적용했습니다. 세 소스 사례 모두 해당 호출 시도나 Office 자동화 패키지 로딩 없이 완료됐습니다. 시험한 보고서 경로를 그 Python 제한 아래에서 확인한 것이며 모든 네이티브 Windows/Shell 호출을 모방하거나 Office를 제거한 것은 아닙니다. 기존 EXE는 따로 시험했으며 최신 소스 변경을 포함하지 않습니다.

생성된 PPTX8개의 ZIP·요약 글자·7×4표·각6개 점인 차트 계열2개·차트 캐시·내장 엑셀을 원본 샘플과 대조했습니다. 반복 저장 시 기존 출력의 바이트도 유지됐습니다. 이번 시험에서는 결과를 검사하거나 렌더링하려고 Office 프로그램을 사용하지 않았습니다. 원본 소스·EXE·입력 해시는 유지됐습니다.

Computer Use 화면 캡처는 시간 초과였고 네이티브 종속 대화상자 조작도 되지 않아 새 시각 검사나 같은 프로세스 안의 UI 오류 복구 통과를 주장하지 않습니다. 선택기 시험 프로세스는 이번 시험의 것임을 확인한 뒤 종료하고 잘못된 입력/재실행 검사는 지원되는 자체 시험 진입점으로 수행했습니다. Windows Sandbox가 없고 사용할 수 있는 Docker/WSL은 Linux이므로 실제 Office 미설치 Windows 시험은 수행하지 않았습니다. Windows 기능·가상 머신·다른 오피스를 설치하지 않았습니다. 별도 실제 사용자 시험은 계속 제외합니다.

## 최신 EXE·실제 Office·깨끗한 Windows 검사(2026-11-08–09)

후속 사용자 요청으로 Office 렌더링과 깨끗한 Windows 시험을 추가했습니다. 변경하지 않은 검사 대상 EXE의 SHA256은 `d19d0404311b22f42fa6dc36edc6c384e591030d59d6906179dae6efe373d64f`입니다. 이 추가 검사 전에 빌드에서 핵심 테스트675개·검증 자체 시험91개·빌드된 EXE 스모크가 통과했습니다.

PowerPoint16.0.20326.20232로 호스트에서 만든 보고서18개와 실제 게스트에서 만든 보고서18개를 읽기 전용으로 열고 각각 슬라이드22장을 내보냈습니다. 각 묶음의 표12개·차트8개에서 계열 값과 범주가 저장된 PPTX와 일치했습니다. 게스트 보고서 PNG22장은 이미 서로 다른16개 이미지로 확인한 호스트 PNG22장과 바이트가 같았습니다. 한글·소수점 서식·ODS 시간 문자열·집계 차트를 읽을 수 있었고 슬라이드 경계 밖으로 나간 도형은 없었습니다. 음수 합성 차트는 템플릿의0축 배치를 유지했습니다. 원본 보고서 바이트를 보존했습니다.

사용자 승인 후 기존 Windows10Pro 설치 ISO와 설치되어 있던 VirtualBox7.2.16으로 새 동적 디스크를 쓰는1CPU·4GBVM을 만들었습니다. 게스트가 보고한 환경은 Windows10Pro 빌드19045.3803이며 Office·별도 Python 설치와 호스트 검증 예외가 없었습니다. 네트워크·공유 폴더·Guest Additions도 사용하지 않았습니다. 읽기 전용 시험 ISO에는 정확한 EXE·라이선스 고지·직접 만든 합성 입력·Windows PowerShell 검사기만 넣었습니다. 실제 게스트 요약·이벤트·보고서는 호스트의 포터블7-Zip26.06으로 비공개 VDI/NTFS에서 읽었습니다. 추출 도구를 게스트에 설치하거나 앱에 추가하지 않았습니다.

게스트의19개 사례가 모두 통과했습니다. 정상→잘못된 입력→정상 재실행, BIFF2/3/4/5와 한글 BIFF5, BIFF8서식 문자열, 중첩 HTML 부모·자식 표, XLSB짧은 셀, ODS시간 표기, 정확한 그룹 합계·평균·곱 집계를 포함합니다. 보고서18개의 글자와 차트 캐시가 확인된 기준과 일치했고 시험 파일·입력 해시도 유지됐습니다. 시험 후 게스트를 종료했습니다. 이 결과는 해당 Windows 10 VM과 산출물의 근거이며 Windows11·다른 물리 PC·사람의 사용 시험·모든 입력과 템플릿까지 보증하지 않습니다. 앱 실행 코드·의존성은 변경하지 않아 재빌드하지 않았습니다. 기존 원본 MIT와 번들 제3자 고지는 그대로이며 비공개 Windows 설치·미디어는 앱 배포물에 포함하지 않습니다.
